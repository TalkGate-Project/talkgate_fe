# 2026-09-04 팀 관리 고도화 수동 QA 가이드

- 작성일: 2026-09-04
- 대상: `7617600`, `474d845` 및 이후 미커밋 수정분
- 대상 화면: 설정 → 팀 관리 → 조직도
- 준비: 팀장·팀원·미배정 구성원이 각각 존재하는 프로젝트, 조직 이동 권한이 있는 관리자 계정
- 환경: Chrome/Edge 우선, 가능하면 Firefox 추가. 브라우저 기본 줌은 먼저 100%로 둔다.

## 가장 먼저 확인할 흐름

아래 1~4가 모두 통과해야 이번 수정의 핵심 문제가 해결된 것으로 본다.

### 1. 전체화면 → 멤버 모달 → Escape

재현:

1. 화면 폭을 1080px 이상으로 맞춘다.
2. 설정 → 팀 관리 → 조직도로 이동한다.
3. 조직도 우측 상단의 전체화면 버튼을 누른다.
4. 아무 구성원 카드를 눌러 직원 정보 모달을 연다.
5. Escape를 한 번 누른다.

통과 조건:

- [ ] 직원 정보 모달만 닫힌다.
- [ ] 조직도 전체화면은 그대로 유지된다.
- [ ] 모달이 닫힌 뒤 조직도 배경이 휠로 스크롤되지 않는다.
- [ ] Escape를 한 번 더 누르면 그때 전체화면이 종료된다.
- [ ] 전체화면 종료 후 페이지 세로 스크롤이 다시 정상 동작한다.

왜 위험한가: `TeamManagementSettings`의 전체화면 Escape 처리와 `BaseModal`의 Escape 처리가 같은 `window` 이벤트를 사용한다. 스크롤 잠금도 두 화면이 함께 소유한다.

### 2. 전체화면 → 조직 이동 확인 모달 → Escape

재현:

1. 전체화면에서 이동 가능한 구성원 카드를 다른 구성원 카드 위로 드래그한다.
2. 조직 이동 확인 모달이 나타나면 Escape를 한 번 누른다.

통과 조건:

- [ ] 이동 확인 모달만 닫히고 실제 조직 이동은 발생하지 않는다.
- [ ] 전체화면은 유지된다.
- [ ] 조직도 캔버스 위치와 확대 배율이 갑자기 초기화되지 않는다.
- [ ] 두 번째 Escape에서만 전체화면이 종료된다.
- [ ] 전체화면 종료 후 진입 전 확대 배율로 정확히 돌아간다.

### 3. 전체화면 → 직원 정보 모달 → 오류 모달

재현:

1. 가능하면 DevTools Network에서 직원 수정 요청을 실패시키거나 오프라인으로 전환한다.
2. 전체화면에서 직원 정보 모달을 열고 저장 작업을 시도해 오류 모달을 띄운다.
3. Escape를 순서대로 누른다.

통과 조건:

- [ ] 첫 번째 Escape는 최상단 오류 모달만 닫는다.
- [ ] 두 번째 Escape는 직원 정보 모달만 닫는다.
- [ ] 세 번째 Escape에서만 전체화면이 종료된다.
- [ ] 각 단계에서 배경 페이지 스크롤이 풀리지 않는다.
- [ ] 마지막 모달과 전체화면이 모두 닫힌 뒤에만 페이지 스크롤이 복구된다.

### 4. 모바일 도구 팝오버 → Escape

재현:

1. 화면 폭을 779px 이하로 맞춘다.
2. 조직도 전체화면에 진입한다.
3. 우측 상단 도구 버튼을 눌러 확대·축소·전체화면 버튼 팝오버를 연다.
4. Escape를 한 번 누른다.

통과 조건:

- [ ] 도구 팝오버만 닫힌다.
- [ ] 전체화면은 유지된다.
- [ ] 다시 Escape를 누르면 전체화면이 종료된다.
- [ ] 팝오버 바깥을 눌렀을 때도 팝오버만 닫힌다.

## 추가로 발견된 상태 조합

### 5. 전체화면에서 목록 보기로 전환

재현:

1. 조직도 전체화면에 진입한다.
2. 상단 헤더에서 목록 보기를 선택한다.

확인 항목:

- [ ] 목록 보기를 누르는 즉시 전체화면이 자동 종료된다.
- [ ] 목록 화면이 잘리거나 빈 화면이 되지 않는다.
- [ ] 페이지 스크롤과 목록 내부 스크롤이 정상 동작한다.
- [ ] 조직도로 돌아왔을 때 진입 전 확대 배율이 복원되어 있다.

### 6. 전체화면 중 반응형 경계 통과

재현:

1. DevTools 반응형 모드에서 1079px로 전체화면에 진입한다.
2. 전체화면을 유지한 채 1080px, 1081px로 차례로 늘린다.
3. 반대로 1081px에서 진입한 뒤 1079px로 줄인다.

통과 조건:

- [ ] 앱 헤더와 조직도 사이에 큰 빈틈이나 겹침이 생기지 않는다.
- [ ] 조직도 우측·하단이 뷰포트 밖으로 잘리지 않는다.
- [ ] 캔버스 확대 배율이 갑자기 튀지 않는다.
- [ ] 전체화면 종료 후 페이지 너비와 스크롤이 정상으로 복구된다.

왜 위험한가: 1080px부터 body `zoom: 0.8`이 적용되며, 전체화면 크기는 화면 px를 body zoom으로 나눠 계산한다.

## 기능별 확인

### 7. 확대·축소·전체화면 복원

1. 진입 전 배율을 최소값 0.6으로 낮춘다.
2. 전체화면에 진입하고 확대·축소를 몇 번 수행한다.
3. 버튼으로 전체화면을 종료한다.
4. 같은 과정을 Escape 종료로 반복한다.

- [ ] 버튼 종료와 Escape 종료 모두 진입 전 배율 0.6으로 돌아간다.
- [ ] 최대 2.0에서 확대 버튼, 최소 0.6에서 축소 버튼이 비활성화된다.
- [ ] 전체화면을 여러 번 반복해도 배율이 누적되거나 변하지 않는다.
- [ ] 휠 확대 후 버튼 확대를 섞어도 범위를 벗어나지 않는다.

### 8. 팀·구성원 바로가기와 강조 링

1. 팀 배지를 누른다.
2. 이름 일부를 입력하고 Enter 또는 검색 버튼을 누른다.
3. 팀장 결과와 팀원 결과를 각각 누른다.
4. 키보드 Tab으로 팀 배지와 검색 결과에 포커스를 이동한다.

- [ ] 선택한 노드가 화면 중앙 근처로 부드럽게 이동한다.
- [ ] 같은 결과를 연속으로 눌러도 매번 이동·강조가 동작한다.
- [ ] 이동한 노드에 초록색 계열 강조 링이 약 1.4초 보인다.
- [ ] Tab 포커스 링이 팀장/팀원 배경과 구분되어 보인다. 🌗 라이트·다크 모두 확인한다.
- [ ] 존재하지 않는 이름은 “일치하는 배정 구성원이 없습니다”로 표시된다.
- [ ] 검색어를 모두 지우면 팀 바로가기 목록으로 즉시 돌아온다.
- [ ] 팀 배지에 대응하는 팀장이 조직도에 없을 때 무반응으로 끝나는 항목이 없는지 확인한다.

### 9. 좌우 엣지 자동 패닝과 드롭

1. 가로로 넓은 조직도에서 구성원을 드래그한 채 왼쪽 가장자리에 댄다.
2. 같은 작업을 오른쪽에서도 수행한다.
3. 가장자리에서 손을 뗀 뒤 다시 일반 노드에 드롭한다.

- [ ] 가장자리에 머무는 동안 해당 방향으로만 계속 이동한다.
- [ ] 가장자리에서 벗어나면 즉시 자동 이동이 멈춘다.
- [ ] 드롭하거나 Escape로 드래그를 취소한 뒤 캔버스가 계속 움직이지 않는다.
- [ ] 좌우 가장자리에 걸친 노드도 강조되고 정상적으로 드롭할 수 있다.
- [ ] 우측 상단의 “소속 해제” 영역과 오른쪽 엣지 패닝 영역이 겹칠 때 원하는 대상에 드롭할 수 있다.

엣지 가이드는 포인터 이벤트를 받지 않으며, 캔버스가 포인터 위치를 계산해 패닝한다. 따라서 가이드 아래 노드도 원래 드롭 대상으로 동작해야 한다.

### 10. 태블릿 미배정 구성원 드로어

화면 폭 779px, 780px, 1079px, 1080px에서 각각 확인한다.

- [ ] 1079px 이하에서는 미배정 구성원이 우측 고정 열이 아니라 드로어로 열린다.
- [ ] 1080px 이상에서는 우측 고정 열로 표시된다.
- [ ] 드로어를 연 상태에서 전체화면 진입·종료 시 드로어가 화면 밖에 남지 않는다.
- [ ] 미배정 구성원을 배정한 뒤 목록에서 중복되거나 사라지지 않는 항목이 없다.
- [ ] 이름 또는 ID가 비어 있는 비정상 데이터가 배정 대상으로 표시되지 않는다.

### 10-1. 이름이 같은 팀이 둘 이상인 프로젝트

같은 이름의 팀(예: `영업2팀`)이 둘 이상 존재하는 프로젝트에서 목록 보기를 연다.

- [ ] 동일한 이름의 부서 필터 버튼은 하나만 표시된다.
- [ ] 해당 버튼을 누르면 같은 부서명을 가진 구성원이 모두 필터링된다.
- [ ] 브라우저 Console에 `Encountered two children with the same key` 경고가 나타나지 않는다.
- [ ] 필터를 선택·해제하거나 조직도와 목록을 왕복해도 버튼이 중복되거나 사라지지 않는다.

## 공용 모달 회귀 확인

오늘 수정은 `BaseModal`의 스크롤 잠금 구현을 공용 유틸리티로 옮겼기 때문에 팀 관리 밖의 대표 화면도 짧게 확인한다.

### 11. 일반 모달 하나

고객 등록, 일정 등록 또는 설정의 연동 모달 중 하나를 연다.

- [ ] 모달이 열린 동안 배경 페이지가 스크롤되지 않는다.
- [ ] 모달을 닫으면 원래 페이지 스크롤이 복구된다.
- [ ] 모달을 3회 연속 열고 닫아도 스크롤이 계속 잠기거나 미리 풀리지 않는다.

### 12. 중첩 모달 하나

작업 실패 등으로 일반 모달 위에 오류 모달을 띄울 수 있는 흐름을 사용한다.

- [ ] 위쪽 모달을 닫아도 아래쪽 모달이 남아 있는 동안 배경은 잠겨 있다.
- [ ] 마지막 모달이 닫힌 뒤에만 배경 스크롤이 복구된다.
- [ ] Escape 한 번에 모달 하나만 닫힌다.

### 13. 스크롤 잠금을 사용하지 않는 플로팅 창

직원채팅 플로팅 창을 연다.

- [ ] 플로팅 창이 열린 상태에서도 기존처럼 배경 페이지를 스크롤할 수 있다.
- [ ] 플로팅 창을 닫는 동작이 다른 일반 모달의 스크롤 잠금에 영향을 주지 않는다.

```js
})
```
