## 0. 상태 조합 시나리오 (가장 중요)

### 시나리오 1 — CLIENT_IP_PROXY_SECRET 미설정 환경에서 배포
재현: 배포 환경(Vercel 등, `x-vercel-forwarded-for` 헤더가 실제로 붙는 환경)에서 `CLIENT_IP_PROXY_SECRET` 환경변수가 설정되지 않은 상태로 로그인/서브도메인 접속 시도.
왜 위험한가: `src/lib/env.ts`의 `getClientIpProxySecret()`은 값이 없으면 `throw`한다. `buildClientIpProxyHeaders`는 `x-vercel-forwarded-for` 계열 헤더가 있을 때만 이 함수를 호출하므로, **로컬 dev(해당 헤더 없음)에서는 절대 재현되지 않고 실제 배포 환경에서만 터진다.** `/api/proxy` 쪽은 try/catch로 감싸 500만 나지만 전체 API가 죽고, `middleware.ts`의 `fetchProjectBySubdomain`도 catch되어 `null` 반환 → 서브도메인 진입이 "프로젝트 없음"처럼 보이게 된다.
- [ ] 1-1. dev/prod 배포 환경변수에 `CLIENT_IP_PROXY_SECRET`이 실제로 설정돼 있는지 먼저 확인 (코드 리뷰가 아니라 배포 설정 화면에서).
- [ ] 1-2. 설정된 배포 환경에서 로그인 → 서브도메인 진입 → 아무 API 호출(고객 목록 등)이 정상 200으로 오는지 확인.
- [ ] 1-3. (가능하면) 환경변수를 임시로 비워 재배포하지 말고, 로그만으로 `[API Proxy] 에러` / `[Middleware] 서브도메인 프로젝트 조회 에러` 로그가 찍히지 않는지로 대체 확인.
