### 시나리오 2 — 월소득/금융자산/차량가액을 입력하지 않고 그대로 "분석하기"를 눌렀을 때

**재현**: 신규 진단 생성 폼에서 다른 필수값은 다 채우고 월 소득/금융자산/차량가액 세 필드는

그런데 스펙 원문은 "필수, 만원. 해당 없으면 0"이라 "0을 명시적으로 선택/입력한 것"과 "그냥 안
건드린 것"을 구분하지 않는다. 결과적으로 상담사가 소득 입력을 깜빡해도 버튼이 막히지 않고
"소득 0원"으로 그대로 분석이 실행된다 — 예전엔 PillSelect 미선택 상태가 "필수 *" 배지로
시각적으로 드러났지만 지금은 그런 신호가 없다.

- [x] 2-1. 월 소득/금융자산/차량가액을 비워둔(0) 채로 "분석하기"가 클릭 가능한지 확인 (의도된
      동작인지는 버그로 단정하지 말고 정책 확인 필요 항목으로 기록) — **확인(id=82, QA테스트B):
      전부 0/무직 상태로 정상 제출·분석 완료(400 에러 없음 — 백엔드가 0을 유효값으로 받아들임)**
- [x] 2-2. 실제로 이렇게 제출된 분석 결과가 이상한 값(가용소득이 실제보다 훨씬 낮게)으로 나오는지
      확인 — **결론: 문제없음.** 월 가용소득 -154만원(0-154-0)으로 수식대로 정상 계산됐고, AI가
      "무직 상태여서 이자 감면·상환기간 조정만으로도 상환 지속성이 부족할 수 있음"을 위험요소로
      자체 표시함 — 프론트에 "필수 *" 표시가 없어도 AI 분석 결과 자체가 저소득/무직 상황을

오늘 바꾼 소득/자산 필드가 다른 기능(상세 채무입력, 새출발기금 게이트)과 교차하는 지점 + 계산
결과가 직관과 어긋나 보일 수 있는 조합(고소득인데 가용소득 마이너스)을 추가로 확인.

- [x] **QA테스트C (id=83)** — 상세 채무입력 모드 + 부양가족 4명 이상(가구원수 경계값 5인,

      -153만원"으로 정확히 인용됨.** 상세입력의 원금/이자 자동계산(총이자 15,115,720원 등)과
      새 소득 필드가 서로 간섭 없이 동작
- [x] **QA테스트D (id=84)** — 사업영위 이력 있음(새출발기금 게이트 ON) + 폐업(개인) + 부실사유
      2종(3개월이상연체·국세지방세체납) + 월소득 0(무직) + 금융자산 5,000만원/차량 1,000만원 +

      "채무 현황" 섹션의 큰 "월 가용 소득" 수치 자체는 음수여도 흰색 기본 텍스트로만 표시됨(목록/폼
      미리보기와 다르게 강조색이 없음) — 버그로 단정하지 않고 **관찰 기록만** 남김(디자인 의도일
      수 있음, Figma 정리 시 같이 판단)

### 🔍 새로 발견한 것 — 프론트 미리보기 vs 서버 실제값, 반올림 경계에서 1만원 차이

QA테스트E에서 처음으로 **프론트 계산식과 서버 실제 `disposableIncome`이 어긋나는 사례**를 발견함.

- 입력: 월소득 500만원, 3인가구 법원 인정 최저생계비 3,215,422원, 추가 필수지출 450만원
- 프론트 계산(`useDiagnosisForm.ts`와 동일 공식): `5,000,000 − 3,215,422 − 4,500,000 = −2,715,422원`
  → `Math.round(-271.5422) = -272`만원. 실제로 폼 미리보기·법정 생계비 표시 행(고객정보 모달)도
  전부 이 값(-272, 법정생계비 322)으로 계산해 보여줌
- **서버 실제 응답의 `disposableIncome`은 -271만원.** 소수점 .5422 지점에서 반올림 방향이 갈려
  프론트와 1만원 차이가 남
- QA테스트A/B/C(각 +28, -154, -153만원)에서는 우연히 .5 근처가 아니어서 안 드러났던 문제로 보임
- **원인 미상** — 서버가 최종값을 반올림이 아닌 다른 방식(예: 각 항을 만원 단위로 절삭 후 계산,
  또는 최저생계비 상수 자체가 여기 표에 적은 3,215,422원과 실제로 10,000원 정도 미세하게 다름)으로
  계산할 가능성 등 여러 시나리오가 있어 코드를 추측성으로 고치지 않았음. **백엔드 팀에 정확한
  반올림 규칙(또는 3인가구 최저생계비 상수를 다시 한번) 확인 필요** — 확인되면
  `resolveCourtMinimumLivingCostWon`/`wonToManwon` 조합을 맞춰 프론트 미리보기를 정확히 일치시킬 것
- **영향도**: 최대 1만원 오차, 그것도 합산값이 반올림 경계(.5 근처)에 걸리는 드문 케이스에서만
  발생 — 상담 실무에 지장을 줄 수준은 아니라 🟢로 분류하되, 반올림 규칙이 확인되기 전까지는
  "미리보기는 참고용, 최종 확정값은 분석 결과 화면 기준"이라고 상담사에게 안내하는 걸 권장
